concurrent writers (`OSError: Errno 22`).

## Bootstrap replicates: default 100 everywhere

`figures/fig01b_examples.py` used to override this with `num_bootreps=200`. It no
longer does — it calls `bootstrap_many` without the argument, so the example panels
and the figures-of-merit tables now draw the same number of replicates. They have to
agree: the panel annotates a peptide's LOQ, and the table reports the LOQ for that
same peptide, and at different replicate counts those were not the same number.

Concretely, on the Exploris examples, 200 → 100 replicates moved **AGLQFPVGR's LOQ
from 0.326 to 0.373 (+14%)**; VFLENVIR (0.649) and YPIEHGIITNWDDMEK (0.651) did not
move at all. A 14% swing from replicate count alone is the Monte-Carlo residual
described in [`loq_stability_note.md`](loq_stability_note.md) — 100 is not
better-converged than 200, it is simply the value the tables use, so it is the value
the panels must use.

## How the legacy_mnp2 provenance was established

Not from a record — by matching. Each `legacy_mnp2/*.csv` has the same row count as
`B/asms/<dataset>/results_auto_noyeast/figuresofmerit.csv` (68,274 / 56,253 / 40,438),
those files are dated May–Jul 2025, and they carry the pre-ULOQ 7-column header
(`peptide,LOD,LOQ,slope_linear,intercept_linear,intercept_noise,stndev_noise`). The
only tool commit in that window is `60d3a9b` (2025-05-28); the next is 2025-09-22.

`60d3a9b` has no `--n_threads` or `--min_saturation_points`, seeds globally with
`np.random.seed(8888)`, and fans peptides out over a default-sized
`ProcessPoolExecutor()`. Because scheduling decides which worker's RNG stream serves
which peptide, a re-run on different core counts is **not** guaranteed to reproduce
these numbers. Treat `legacy_mnp2/` as a frozen artifact.

## Reproducing a row

```bash
python tools/matrix-matched_calcurves/bin/calculate-loq.py \
    <input> <map.csv> --model auto --plot n \
    --min_noise_points <N> --min_saturation_points 2 \
    --n_threads 6 --output_path <local_dir>
# then copy <local_dir>/figuresofmerit.csv to data/figuresofmerit/<...>.csv
```

Roughly 0.8 peptides/s per worker on an 8-core / 16 GB box, so a 60,000-peptide
dataset is a ~4 hour run at 6 threads. The 1.2 GB DIA-NN reports take the parent
process to ~4 GB resident and must be run **one at a time** on a 16 GB machine.

## Open decision that affects every number here

`docs/loq_stability_note.md` records that the bootstrap uses unstratified case
resampling, which is the dominant source of LOQ instability (up to 310% spread on one
sample peptide, 0.0% under stratified resampling), and that adopting stratified
resampling is a decision to make *before* regenerating figures of merit. As of
`ffb1087` the tool still uses case resampling
(`bin/calculate-loq.py` → `_bootstrap_once`), and every CSV above was produced under
it. If that scheme changes, everything in this table needs regenerating again.
